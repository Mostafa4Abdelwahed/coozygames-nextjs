# Features — Payments

## 1. صفحة المستخدم `/premium`

### الغرض
يعرض السعر الحالي للخطة الشهرية، طرق الدفع، نموذج إرسال دفعة، حالة الاشتراك،
وسجل الدفعات الخاص بالمستخدم.

### المصدر
`getMonthlyPrice()`, `getPaymentMethods(enabledOnly=true)`, `getMyPayments(userId)`,
`getSubscriptionForUser(userId)` — كلها في `lib/billing.ts`.
السعر يُقرأ من `app_settings('PREMIUM_MONTHLY_PRICE')`.

### الواجهة (ثيم ليلي عام)
- **Hero الحالة:**
  - اشتراك فاعل → "اشتراكك نشط حتى {تاريخ}" + "+{أيام} يوم متبقية" + نسب "تجديد".
  - فيه دفع `pending` → "دفعة قيد المراجعة".
  - غير دا – CTA "اشترِ الآن بـ {سعر} ج.م/شهر".
- **فورم الدفع** (`premium-panel.tsx`):
  - شريحة لطرق الدفع المفعلة (كل بطاقة: اسم + `details` — رقم المحفظة/الاسم).
  - رقم العملية (`text`, إجباري) + اسم المُرسِل (إجباري) + ملاحظة (اختياري).
  - رفع صورة إيصال: `accept="image/*"`, preview فوري، "حد 5MB".
  - زر "إرسال الدفعة" → `submitPayment` action.

### الحالات الطرفية
- غير دخيل → زر دخول/تسجيل (الـ action يرفض بدونه).
- الملف أكبر من 5MB → رفض مع رسالة.
- صيغة غير صورة → رفض.
- السعر الحالي يتغير بعد فتح الصفحة → الـ action يلتقط السعر الجديد (قيمة من DB).

## 2. الداشبورد `/dashboard/billing`

### الغرض
مركز تشغيل الدفع اليدوي: المراجعة، سعر الخطة، طرق الدفع.

### المصدر
`listPaymentsForAdmin(filters, page)` (يربط الـ user + method)، `billingSummary()`,
`listPaymentMethodsAdmin()` من `lib/billing.ts`.

### الواجهة (ثيم فاتح shadcn)
- **ملخص:** كروت صغيرة — معلّقة، موافقة هذا الشهر، إيراد هذا الشهر، مشتركين نشطين.
- **الطلبات:** جدول (حسب نمط `/dashboard/users`):
  - فلتر status (`pending`/`approved`/`rejected`/الكل) + ترقيم.
  - كل صف: المستخدم، الطريقة، المبلغ، رقم العملية، المُرسِل، الحالة (Badge)، التاريخ.
  - ديالوج **عرض/قرار**: صورة الإيصال (من `/api/uploads/receipt/[id]`) + حقل ملاحظة +
    أزرار "موافقة"/"رفض" → `reviewPayment`.
- **سعر الخطة:** حقل رقمي يُحفظ عبر `saveMonthlyPrice` → `app_settings` + revalidate.
- **طرق الدفع:** كروت/جدول: اسم + details + مفتاح enabled + حذف/تعديل عبر
  `addPaymentMethod` / `updatePaymentMethod` / `deletePaymentMethod`.

### الحالات الطرفية
- موافقة على دفعة `pending` فقط؛ أي محاولة على صف محسوم → رفض منطقي (لأمان إعادة
  التمديد المتكررة — نتحقق `status='pending'` في نفس الـ UPDATE).
- رفض لا يمس الاشتراك.
- طريقة دفع وحيدة متبقية — يظل الرفض/الحذف مسموح (يحذر ببساطة لو عدالة خيارات).

### الملاحظة (Audit)
جميع الكتابات تُسجَّل عبر `logAudit(..., 'billing.*', ...)`.

## 3. Gating اللعب

### الغرض
منع تشغيل الألعاب غير المشتركين مع إبقاء التصفح 100% مفتوح.

### المصدر
`isPremiumActive(userId)` → `SELECT expires_at FROM subscriptions WHERE user_id=$1` ثم
تحقق `expires_at > now()`.

### الواجهة
في `app/play/[slug]/page.tsx`: عند عدم الفاعلية تُعرض `SubscriptionGate`:
- أيقونة بريميوم، العنوان "الاشتراك مطلوب لتشغيل الألعاب".
- سطر السعر "اشترك بـ {سعر} ج.م/شهر".
- غير دخيل: زر "تسجيل الدخول" + زر "عرض الخطط".
- دخيل: زر "الاشتراك الآن" → `/premium`.

### الحالات الطرفية
- مستخدم مشترك → يمر إلى `GameStage` بشكل طبيعي.
- زائر (بدون جلسة) → يُعامل مثل غير مشترك مع CTA دخول.
- لعبة مش موجودة → `notFound()` كالمعتاد.
- **لا** يُسلَّم `playUrl` إلى الـ client و**لا** يُسجَّل `play_event` لطلبات ممنوعة.
